Strong yes — for this project PR previews are unusually valuable, and here's why: the riskiest things in this app are platform behaviors that unit tests can't see — File.stream() inside a Web Worker on the deployed origin, the strict CSP actually being served, SPA routing on Workers static assets, worker module loading in production builds. A preview URL per PR means we validate those in the real Workers runtime before merge instead of discovering breakage on the live site. It also gives you something clickable to review for the UI-heavy WPs (07/08) — much better than reading JSX.

The good news is the architecture we already picked gives you both halves for free:

  • Workers Builds (D15) deploys production on every push to main — that's your "merge triggers a deployment."
  • The same connection does preview builds for PR branches, each with its own preview URL posted as a PR check — no CLOUDFLARE_API_TOKEN secret in GitHub, which keeps the no-stored-credentials property that drove D15.

Two caveats worth knowing, neither blocking: preview URLs are public (fine — the app is static, open source, and processes nothing server-side), and previews only build for branches in your repo, not fork PRs (that's the safe default for a public repo anyway).

I've noted this as an explicit WP-09 requirement in the plan since you've raised it twice:

Based on the search results, here's information about Cloudflare Workers Builds preview URLs with GitHub integration:

## Overview

When you connect your Cloudflare Worker to a git repository on GitHub, each branch of your repository has its own stable preview URL that you can use to preview code changes before merging the pull request and deploying to production.

## Preview URL Features

These preview URLs are named after your branch and are posted as a comment to each pull request, with the URL staying the same with every commit and always pointing to the latest version of that branch.

Each comment includes two preview URLs: a Commit Preview URL unique to the specific version/commit, and a Branch Preview URL which is a stable alias based on the branch name.

## GitHub Integration Capabilities

If a commit is on a pull request, Cloudflare will automatically post a comment on the pull request with the status of the build, and a preview URL will be provided for any builds which perform wrangler versions upload.

Both preview URL types follow the format: &lt;VERSION_PREFIX OR ALIAS&gt;-&lt;WORKER_NAME&gt;.&lt;SUBDOMAIN&gt;.workers.dev.

Preview URLs are integrated into CI/CD pipelines, allowing automatic generation of preview environments for every pull request.
